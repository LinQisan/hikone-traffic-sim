# 项目渲染性能优化

> 2026-10-01 晚：浏览器版不再支持 VR（只面向电脑和手机浏览器），下文第一轮里关于 VR 面板和 VR 回放的条目已随之移除。动态分辨率现在在绘制之前调整画布尺寸（之前在绘制之后调整，会让浏览器显示一帧空白，看起来像闪烁），并且需要连续 3 个窗口都有余量才会升回去。

## 第二轮：合并绘制调用（2026-10-01 下午）

用无头 Chrome（ANGLE/Metal，AMD Radeon Pro 5300M）测量，视口 1280×720、DPR 2，按默认上限渲染为 1600×791。测量期间这台 Mac 被其他程序占满 CPU，系统把 CPU 限速到 22%～37%，同一配置前后两次的帧率能差 5 倍。所以下表不用"分别打开页面测帧率"，而是**在同一页面里同时建好新旧两套环境，同一段时间内逐帧交替渲染**，每帧用 `readPixels` 强制同步，并用 `EXT_disjoint_timer_query_webgl2` 记录 GPU 时间（街景视角，各 30 帧取中位数）：

| 街景 | 旧：按颜料的 BatchedMesh | 新：按资产的 InstancedMesh |
| --- | ---: | ---: |
| 绘制调用 / 实际子绘制 | 54 / 约 3,900 | 117 / 117 |
| 整帧（提交 + GPU，同步） | 56.8 ms | 34.9 ms |
| GPU 时间 | 42.8 ms | 29.3 ms |
| `renderer.render` 的 CPU 时间（正常 rAF 循环） | 约 29 ms | 约 2 ms |

上一轮的批处理在每种颜料内为每个物体（以及大资产的每个 16 米小块）保留一个子绘制。Mac 上的 ANGLE/Metal 和移动 GPU 没有原生的多重绘制，约 3,900 个子绘制要在驱动里逐个执行：只留草地一个批次（2,101 个子绘制、约 2.3 万三角形）就要 17 ms，去掉整个城区则约 2 ms。CPU 剖析里的时间大多停在 `uniformMatrix4fv`、`multiDrawElementsWEBGL` 等 WebGL 调用上，这是在等驱动。

改动：

- **一个共享材质**（`PigmentPalette`，`src/style.js`）：所有城区颜料都是不透明、白色基色加顶点颜色，彼此只差暖/冷色、笔触强度和自发光。每个顶点带一个颜料编号（`hkPigment`），在顶点着色器里从 4×64 的小纹理读取这些参数。笔触、纤维和冷色阴影的着色代码和以前相同（`injectPaint` 同时供单独材质和共享材质使用）。
- **每个资产每个细节级别一次绘制**（`src/environment-instances.js`）：资产的各部件在加载时合并成一个几何体（高、低细节各一个），所有配置画成一个 InstancedMesh。CPU 每帧（视角不变时跳过）按包围球选出视锥内或阴影框内的配置，按 60 / 52.8 米的滞后阈值决定细节级别，再由近到远排序（利于提前深度剔除）。
- **阴影只画阴影框内的物体**：实例列表把阴影框内的配置放在前面，阴影 pass 通过 `onBeforeShadow` 只画这一段。以前车辆移动时阴影每秒重绘 20 次，每次都会把视野里所有远处物体再画一遍。
- **大资产按粗格切块**：宽度超过 100 米的唯一资产（抬高道路、远处地面、铺装地面、城山地形）按至少 64 米的格子切开，每格高、低细节各一个网格，交给 three.js 按包围盒裁剪。每个原始三角形只进入一个格子（测试逐个比对）。
- **动态分辨率**（`src/resolution.js`，仅桌面）：每 0.5 秒看一次平均帧时间，低于约 50 FPS 就把像素比乘以 0.85（最低 50%），有余量时乘以 1.1 回升；刚降过的级别在 6 秒内作为上限，避免来回跳。FPS 显示里的百分比就是当前比例。`benchmark=1` 和 `quality=high` 时固定不变；VR 和隐藏标签页不参与。片元（像素）开销约占 GPU 时间的一半，这一项在慢的 GPU 上效果最大。
- **请求高性能 GPU**（`powerPreference: 'high-performance'`）：双显卡 Mac 默认会落到核显上。在这台机器上，同一视角从 Intel UHD 630 换到 Radeon 5300M，帧率约翻一倍。

在新路径上用 GPU 计时拆分街景（同一会话，ms）：完整 33.4；像素降到 1/16 时 19.7；换成最简单的材质 25.0。所以剩下的开销大约一半在像素着色、一半在几何。把法线/颜色补齐到 4 字节对齐没有差别。

没有做到的：加载和构建的时间没有可靠的对比（受机器负载影响太大）；动态分辨率在真实浏览器里的收敛过程只用单元测试验证过（无头模式关闭了垂直同步，帧间隔分布和真实浏览器不同）。

## 第一轮（2026-10-01 上午）

2026-10-01，在本机 Codex 内置浏览器中测量。浏览器视口为 1280×720。优化前按 DPR 2 渲染，高清对照保持相同的 2560×1440 帧缓冲；默认模式按 DPR 1.25 渲染，实际帧缓冲为 1600×900。相同分辨率的提升约为两倍，默认模式进一步控制像素开销。

| 场景 | 优化前 FPS | 同分辨率优化后 FPS | 默认模式优化后 FPS |
| --- | ---: | ---: | ---: |
| 固定街景 | 7.9 | 16.4 | 21.7 |
| 动物与车辆回放 | 7.5 | 15.1 | 23.8 |

帧率按采样帧间隔的平均值计算，不使用截断到 0.1 秒的模拟步长。探针排除前 2 秒及跨过预热边界的一帧，通常继续采样约 8 秒。首次加载仍可能出现着色器编译停顿；设备温度、浏览器和其他负载会影响结果。表中采用最终实现的记录，不承诺固定帧率。回放使用同一段检查录制，包含移动、接触慢动作和结束后的停留，绘制统计取窗口平均值。

| 固定街景的工作量 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 每帧绘制调用（含当帧阴影） | 287 | 54 |
| 每帧三角形（含当帧阴影） | 7,839,644 | 942,477 |
| 更新逻辑耗时 | 0.06 ms | 0.22 ms |
| 帧时间中位数（相同分辨率） | 126.5 ms | 61.1 ms |

更新逻辑原本就很轻，主要瓶颈在提交几何和 GPU 绘制。此次调整如下：

- 保留高精细模型，为 56 个资产生成 `.lod.glb`。远景移除多数独立的细小笔触，保留基础形体、顶点颜色和轮廓极值。现有模型用 `--lod-only` 直接处理保存的 GLB，避免重新生成树冠。全城 1260 个物件全部使用远景级别时，三角形从 4,376,924 降到 1,205,756。
- （已由第二轮取代）支持 `WEBGL_multi_draw` 时按相同材质和投影设置组成 BatchedMesh，每个物件保留原来的行列、独立视锥裁剪及几何级别。60 米外切换远景，回到 52.8 米内恢复高精细级别，避免来回闪烁。WebXR 回放同时考虑体感视点和回放摄像机。非支持设备回退到 64 米区块的 InstancedMesh 与 LOD。
- 将逐像素的笔触噪声计算改为一次生成的 512×512 查找纹理，带 mipmap；画法仍锚定在世界表面。场景使用拡散材质，天空只生成一次立方体纹理，移除每帧天空噪声和漫反射材质不需要的 PBR 环境光。
- 阴影贴图从 2048 降到 1024，保留标准 PCF 滤波。静止场景复用贴图；车辆和回放运动时最多约 20 Hz 更新，摄像机移动以及增加、删除物件会使缓存失效。动态阴影没有被关闭。
- 桌面默认 DPR 不超过 1.25，渲染像素不超过 160 万；`quality=high` 保留 DPR 2 上限。摄像机远裁剪面缩到 500 米，超过 430 米雾的范围。
- 复用车辆调色材质。回放结束后停止重复计算动物姿势；文字没变化时不重画和上传 VR 面板，也不重复标记图像材质需要编译。VR 内的回放图片为 960×540、最多 30 Hz；头部视点继续按 WebXR 调度绘制。桌面回放使用主画布。

`npm test` 的 21 项测试通过，包含原有逻辑和模型约束，以及真实城市全部行列、LOD 切换、轮廓和预算、面板更新缓存、VR 回放绘制节流、阴影缓存及动态失效。浏览器验证街景、回放、重新播放、结果页、重新体验和普通实例化回退路径均正常，没有控制台警告或错误。此次没有连接 Quest，未测量真实头显帧率。

复测方式：

```bash
node serve.mjs
npm test
```

访问 `http://127.0.0.1:8770/?view=street&benchmark=1` 或 `?view=replay&benchmark=1`。相同分辨率对照增加 `&quality=high`（`batching=off` 已随第二轮移除）。采样完成后，`#fps` 的 `data-benchmark` 属性含 JSON：FPS、帧时间中位数与 P95、更新耗时、绘制调用、三角形和实际帧缓冲尺寸。`multiDraw` 表示驱动是否支持该扩展（第二轮起不再使用）。

原始数据在 [performance/](performance/)：`street-before.json`、`replay-before.json`、`street-after-high.json`、`replay-after-high.json`、`street-after.json` 和 `replay-after.json`。高清对照记录于相同最终着色实现的验证阶段，默认数据为收尾复测；它们是独立采样窗口。
