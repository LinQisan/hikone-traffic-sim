# 渲染性能

更新：2026-10-02。面向电脑和手机浏览器。

## 本轮实测

内置浏览器，固定 1280×720 视口和帧缓冲，关闭动态分辨率；旧版本为 `b23e8a9`。预热 2 秒后采样约 8 秒，分别打开页面，街景前后与回放新版各复测一次。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 街景 FPS | 12.2–12.5 | 17.1–19.7 |
| 自行车回放 FPS | 17.6 | 16.6–18.3 |
| 环境几何缓冲 | 33.25 MiB | 31.55 MiB（−5.1%） |
| 每顶点颜料纹理读取 | 4 次 | 3 次 |

街景采样有提升，回放尚无稳定提升；机器负载和温度会影响结果，以上不是设备帧率保证。原始数据在 [performance/](performance/) 的 `*-20261002-*.json`，历史记录也保留在那里。

## 优化方案

- 资产按 InstancedMesh 合并绘制，共享顶点颜料材质。大地面分块上限从 280 米缩至 128 米；小块按自身顶点数使用 16 位索引，保留全部原始三角形。
- 颜料强度与暖色共用一个纹理像素，减少一次读取；颜色和自发光保留浮点精度。摄像机比例变化时才重算投影，并先更新投影再裁剪。
- 保持 60 / 52.8 米的远景 LOD 滞后阈值、视角移动后更新实例列表、约 12 Hz 的局部阴影、缓存笔触与天空。
- 桌面动态调整分辨率（默认 DPR ≤1.25、≤160 万像素），手机关闭 MSAA；`quality=high` 固定高清。

50 项测试通过，包含道路和远处地面的高低细节三角形比对、颜料精度与回放。浏览器检查重播、视角切换和点击进入结果页正常，无警告或错误。真实手机性能仍需设备复测。

## 复测

运行 `npm test`、`node serve.mjs`，固定窗口尺寸，打开 `http://127.0.0.1:8770/?view=street&benchmark=1` 或 `?view=replay-bicycle&benchmark=1`。`benchmark=1` 关闭动态分辨率；采样 JSON 在 `#fps` 的 `data-benchmark` 属性中，包含帧率、帧时间、绘制量和帧缓冲尺寸。对照需保持相同视角、分辨率和机器负载。
