# Art and performance

How the web-authored models are built and checked, and what the scene costs to render. Why: [../RATIONALE.md](../RATIONALE.md). Raw benchmark samples: [performance/](performance/).

## Models

`tools/export_models.py` turns VRLearn's generators into `data/models/*.glb`; `tools/build_impressionist.py` rebuilds each into `data/models/impressionist/` (the runtime set: vertex pigments, brush strokes, a distant LOD, `manifest.json`). Houses and trees get new silhouettes. Lamps, utility poles, signals, vehicles and speed signs are authored as closed solids in `tools/abstract_props.py`: a few weighty colour planes, only the outlines needed to read the object. Browser-only `ART_PathLamp`, `ART_UtilityPole` and `ART_MoatUtilityPole` need no upstream raw GLB.

The lamp and five vehicle generators were also ported to VRLearn's `Art/Hikone/hk_web_props.py` (D39). Raw exports now contain those same hulls; the Unity sedan is named `HK_Sedan`. The exporter includes mesh children, while Unity centres wheel pivots during prefab generation. The browser continues to use its existing impressionist models and steering code.

VRLearn also ports the earlier car/pedestrian head geometry through `hk_signals.py` (D41). The browser's subsequently narrowed vehicle head is owned here; the pedestrian head retains the upstream geometry. Unity runs a synchronized signal cycle; the browser's signals remain static. `data/signals.json` retains the original reference meshes and matrices for upstream export, but the browser no longer places heads from those cube anchors. Its five installations are authored in `src/signal-layout.js`, independently of a full sync. Pole locations fit the imported map's pavement boundaries; they are not a georeferenced survey.

- **Foliage painting:** `tools/vegetation.py` owns the trees. Broadleaf trees follow the owner's autumn game concept sheet: bent, flared trunks, six spreading primary boughs, branching tips and overlapping three-dimensional leaf sprays. Green shadow pockets transition into coherent gold/orange boughs; evergreen woodland keeps more green. Each near spray contains four smaller groups of 24 broad, folded leaves, using six vertices and eight triangles per blade. Blade area compensates for the reduced count. Blades are thin closed volumes with shared smooth normals, so the existing single-sided packed environment material can see them from the pavement as well as above. Coincident reversed polygons would be removed by the export weld. `ART_TreeBark` carries warm grey/ochre grain and narrow raised flakes in baked pigments. Pine/cedar boughs and low shrubs retain their previous tuft geometry and green palette. ## Performance

What keeps the budget:

- One `InstancedMesh` per asset and LOD (~120 draws, ~3,900 before); large ground cut into ≤ 128 m cells; ordinary-asset LOD at 60/52.8 m and repeated-tree LOD at 24/21.12 m (distance from the bounding-sphere surface); instance lists rebuilt only after the view moves.
- **Shadows:** the sun's map holds only still things, drawn from the light LOD by shadow-only instanced meshes with their own caster list (shown only on frames that redraw it). View LOD switches never touch it; it is redrawn when the shadow box re-centres (4 m). Moving things carry a shadow pool (`src/blob-shadow.js`) instead.
- Dynamic resolution on desktop (DPR ≤ 1.25, ≤ 1.6 Mpx), backing off when a raise fails (each change resizes the canvas); no MSAA on phones; `?quality=high` fixes full resolution.
- Three palette reads per vertex; cached brush textures and sky; positions written in place in hot paths.

### Runtime audit, 2026-10-18

The baseline is the working tree at the start of this review, including the owner's existing scene, road and castle changes. It is not `HEAD`. No models, placement rules, scenario JSON or collision grids were changed by this optimization. [Raw staged measurements and verification](performance/runtime-optimization-20261018.json) identify the source snapshots and retain timing outliers.

The audit covered environment merging/cells/LOD, shader and texture sharing, shadow passes, loading caches, traffic and player updates, body collision, recording, replay animation/camera queries, and resource disposal. All source modules are reachable from the application or editor. No unrelated development tools or model generators were removed.

Changes were checked in three stages:

1. **Resource residency.** Environment high/low GLBs are temporary merge inputs rather than entries in the reusable model cache. Camera obstacles share independent position/index copies per source geometry, allowing the original GLB backing stores and unused normal/colour attributes to be collected. Vehicles and signal parts keep their reusable cache. Failed reusable loads can be retried. The first stage passed 18 performance/camera tests and kept the same static draw/triangle counts. Static-page `Runtime.getHeapUsage().backingStorageSize`, after explicit GC, fell from approximately 59.23 MB to 43.42 MB (26.7%). This is browser backing storage, not GPU VRAM or peak loading memory. Rebuilding an environment again would fetch its merge inputs again; the application builds one city per page.
2. **Culling and uploads.** Persistent slot indices replace temporary per-LOD placement arrays. Matrix data is written only for changed slots and uploaded only when an ordered list changes; shrinking a list only changes its draw count. Layout order, the 60/52.8 m hysteresis, cell size, culling margin, and separate shadow lists remain. Quaternion-based view tracking includes camera roll; second-camera and shadow projections also invalidate their cached lists. Focused checks cover unchanged uploads, restored visibility and all three projection/rotation changes. Five steady CPU batches of 500 moving-view updates are retained in the raw record; they exclude renderer/driver/GPU time.
3. **Simulation and replay.** `GroundContact` computes the exact world minimum Y required by landing, prunes rigid meshes whose transformed local bounds cannot be lowest, and avoids full per-vertex `Box3` expansion. It retains the same contact height under nested rotations and nonuniform scales. Vehicle path samples reuse output objects, dead cars compact in place, and app synchronization no longer creates a live-ID set each frame. Recorded-track lookup uses binary search with the existing angle, duplicate-key and endpoint semantics. Replay cleanup releases tracks, posed groups and the persistent driver camera's parent reference. Nine 500-frame bicycle-replay CPU batches, with the first batch excluded, had median cost about 0.321 → 0.045 ms/frame (86% lower). This microbenchmark excludes rendering and does not imply an 86% FPS gain. `GroundContact` is for the current rigid meshes; skinned or morph-target bodies would need a deformation-aware path.

The visual check found an existing first-frame shadow omission: the sun camera's configured ±45 m volume was still using its default ±5 m projection when the first caster list was built. The projection is now updated before that list. Some opening roof shadows are consequently more complete, and more caster geometry is uploaded initially. Moving objects still never enter the sun map, and stationary frames reuse it. Scene geometry and instance arrays occupy an unchanged 20,340,898 bytes.
