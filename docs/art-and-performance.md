# Art and performance

How the web-authored models are built and checked, and what the scene costs to render. Why: [../RATIONALE.md](../RATIONALE.md). Raw benchmark samples: [performance/](performance/).

## Models

`tools/export_models.py` turns VRLearn's generators into `data/models/*.glb`; `tools/build_impressionist.py` rebuilds each into `data/models/impressionist/` (the runtime set: vertex pigments, brush strokes, a distant LOD, `manifest.json`). Houses and trees get new silhouettes. Lamps, utility poles, signals, vehicles and speed signs are authored as closed solids in `tools/abstract_props.py`: a few weighty colour planes, only the outlines needed to read the object. Browser-only `ART_PathLamp` and `ART_UtilityPole` need no upstream raw GLB.

The lamp and five vehicle generators were also ported to VRLearn's `Art/Hikone/hk_web_props.py` (D39). Raw exports now contain those same hulls; the Unity sedan is named `HK_Sedan`. The exporter includes mesh children, while Unity centres wheel pivots during prefab generation. The browser continues to use its existing impressionist models and steering code.

VRLearn also ports the car/pedestrian head geometry through `hk_signals.py` (D41). Unity runs a synchronized signal cycle; the browser's signals remain static. `data/signals.json` retains the original reference meshes and matrices for upstream export, but the browser no longer places heads from those cube anchors. Its five installations are authored in `src/signal-layout.js`, independently of a full sync. Pole locations fit the imported map's pavement boundaries; they are not a georeferenced survey.

## Performance

What keeps the budget:

- One `InstancedMesh` per asset and LOD (~120 draws, ~3,900 before); large ground cut into ≤ 128 m cells; LOD at 60 m with hysteresis; instance lists rebuilt only after the view moves.
- **Shadows:** the sun's map holds only still things, drawn from the light LOD by shadow-only instanced meshes with their own caster list (shown only on frames that redraw it). View LOD switches never touch it; it is redrawn when the shadow box re-centres (4 m). Moving things carry a shadow pool (`src/blob-shadow.js`) instead.
- Dynamic resolution on desktop (DPR ≤ 1.25, ≤ 1.6 Mpx), backing off when a raise fails (each change resizes the canvas); no MSAA on phones; `?quality=high` fixes full resolution.
- Three palette reads per vertex; cached brush textures and sky; positions written in place in hot paths.

### Download and load size (2026-10-18)

`tools/quantize_glb.py` stores GLB normals as normalized bytes (`KHR_mesh_quantization`) and vertex pigments as normalized unsigned bytes; positions and indices stay float32/exact. The browser already merged every asset into byte normals and pigments (`mergeParts`, `packPigments`), so colours are bit-identical at runtime and normals differ by at most half a byte step. `build_impressionist.py` quantizes every export; the same command re-encodes existing files and updates `manifest.json` sizes. `compactAttributes` (`src/geometry-budget.js`) unpacks the 4-byte-strided byte views once at load, and `mergeParts` rescales byte arrays in one pass. The simulator now loads `data/walls.json` (water walls, 11 KB) instead of `map.json` (about 1 MB, editor surfaces). The moat chain fence's individually modelled links (1,720 triangles per 2 m segment, 11–13 % of a street view's submitted triangles) become one sagging chain line (344 triangles including the post).

Interleaved A/B against `0065f75` from a detached worktree, four rounds per view ([raw samples](performance/asset-quantization-20261018.json)): transferred bytes 43.9 → 27.4 MB (-38 %); submitted triangles street 441,388 → 416,620 and street-east 402,371 → 367,971; calls unchanged (94/72); resident environment geometry unchanged at 21.0 MB. Median uncapped frame time stayed within noise (street 6.7 → 6.8 ms, street-east 5.8 → 6.1 ms) and median ready time moved 11.0 → 10.4/9.9 s: on this integrated GPU these views are not limited by triangle count, so the gain is download and parse, not FPS. Uncapped headless runs show queue back-pressure spikes in p95; use averages, or vsync-capped p95 for smoothness. The vendored three.js is the unminified build (2.1 MB); the minified files of the same release would reduce script transfer further. No real phone was measured.

### Runtime audit, 2026-10-18

The baseline is the working tree at the start of this review, including the owner's existing scene, road and castle changes. It is not `HEAD`. No models, placement rules, scenario JSON or collision grids were changed by this optimization. [Raw staged measurements and verification](performance/runtime-optimization-20261018.json) identify the source snapshots and retain timing outliers.

The audit covered environment merging/cells/LOD, shader and texture sharing, shadow passes, loading caches, traffic and player updates, body collision, recording, replay animation/camera queries, and resource disposal. All source modules are reachable from the application or editor. No unrelated development tools or model generators were removed.

Changes were checked in three stages:

1. **Resource residency.** Environment high/low GLBs are temporary merge inputs rather than entries in the reusable model cache. Camera obstacles share independent position/index copies per source geometry, allowing the original GLB backing stores and unused normal/colour attributes to be collected. Vehicles and signal parts keep their reusable cache. Failed reusable loads can be retried. The first stage passed 18 performance/camera tests and kept the same static draw/triangle counts. Static-page `Runtime.getHeapUsage().backingStorageSize`, after explicit GC, fell from approximately 59.23 MB to 43.42 MB (26.7%). This is browser backing storage, not GPU VRAM or peak loading memory. Rebuilding an environment again would fetch its merge inputs again; the application builds one city per page.
2. **Culling and uploads.** Persistent slot indices replace temporary per-LOD placement arrays. Matrix data is written only for changed slots and uploaded only when an ordered list changes; shrinking a list only changes its draw count. Layout order, the 60/52.8 m hysteresis, cell size, culling margin, and separate shadow lists remain. Quaternion-based view tracking includes camera roll; second-camera and shadow projections also invalidate their cached lists. Focused checks cover unchanged uploads, restored visibility and all three projection/rotation changes. Five steady CPU batches of 500 moving-view updates are retained in the raw record; they exclude renderer/driver/GPU time.
3. **Simulation and replay.** `GroundContact` computes the exact world minimum Y required by landing, prunes rigid meshes whose transformed local bounds cannot be lowest, and avoids full per-vertex `Box3` expansion. It retains the same contact height under nested rotations and nonuniform scales. Vehicle path samples reuse output objects, dead cars compact in place, and app synchronization no longer creates a live-ID set each frame. Recorded-track lookup uses binary search with the existing angle, duplicate-key and endpoint semantics. Replay cleanup releases tracks, posed groups and the persistent driver camera's parent reference. Nine 500-frame bicycle-replay CPU batches, with the first batch excluded, had median cost about 0.321 → 0.045 ms/frame (86% lower). This microbenchmark excludes rendering and does not imply an 86% FPS gain. `GroundContact` is for the current rigid meshes; skinned or morph-target bodies would need a deformation-aware path.

The visual check found an existing first-frame shadow omission: the sun camera's configured ±45 m volume was still using its default ±5 m projection when the first caster list was built. The projection is now updated before that list. Some opening roof shadows are consequently more complete, and more caster geometry is uploaded initially. Moving objects still never enter the sun map, and stationary frames reuse it. Scene geometry and instance arrays occupy an unchanged 20,340,898 bytes. Environment geometry alone is 18,852,206 bytes; the old 21,062,523-byte report double-counted shared shadow geometry. That accounting correction is separate from the measured backing-store saving.

Street GPU mean was 3.74 → 3.61 ms; bicycle replay at 4.7 s was 2.447 → 2.449 ms, with the same 71 draws and 112,637 triangles. Replay CPU update plus renderer submission averaged 2.60 → 1.75 ms in this check. Each 120-draw sequence took approximately two seconds. These measurements support lower CPU work with similar steady GPU cost, while the frame-scheduling outliers above remain unresolved. A later macOS diagnostic reported a 55% CPU speed limit; it does not establish the cause of every timing outlier.

The existing rendering structure is retained deliberately:

- Merged pigment geometry plus `InstancedMesh` already keeps these views below the approximate 120-draw budget. Replacing it with `BatchedMesh` would add batching state and a multi-draw dependency without measured benefit here.
- Large ground retains spatial cells; the distant hill remains one compact silhouette draw. Landmark low detail, near-street high detail, and the existing packed normals/colours already address geometric bandwidth. The bridge and reviewed frontages are significant near-view submissions, where reducing detail would alter the requested appearance.
- The shared 512² brush texture, 3 × 64 float pigment palette, baked 512² cube sky and cached 1024² sun shadow remain. Static views report eight renderer textures, bicycle replay nine. Renderer counts are not byte-accurate VRAM measurements.
- Fog-only removal was rejected: fogged surfaces still write depth against the distant landmark and meet a painted sky. Distance alone cannot safely discard them. No new occlusion system, post-processing, LOD distances or arbitrary renderer height offsets were added.
- Body collision already queries a small 0.2 m grid neighbourhood. Town ray tests and replay viewpoint search run during planning; they are not rebuilt each animation frame. Built-in traffic has few vehicles. A new BVH or moving-actor spatial tree was not justified by the profile, and would increase lifecycle and correctness costs.

Verification: all 129 regression tests passed with zero skips, including all ten event checks. A seeded old/new traffic comparison covered 72,000 steps across ten events and three seeds, including long steps, triggers, contact and frozen traffic; numeric states matched exactly. At 1280 × 720, street, overhead, castle, walking replay and bicycle replay images matched pixel-for-pixel after refreshing both versions' shadow caches; replay captures used time 4.7 s. This comparison deliberately separates the initial-shadow correction above. Eight rendered replay start/stop cycles kept renderer geometry/texture/program counts stable and released recording/camera-parent references. Browser checks covered walking/riding keyboard movement, Q look, menu exit, both replay viewpoints, replay restart/end/results/focus, 390 px touch targets, reduced motion and forced colours, with no console or page errors. Real phones and headsets, peak memory and exact VRAM were not measured.

### Measuring

Open `http://127.0.0.1:8770/?view=street&benchmark=1` (or `view=replay-bicycle`) at a fixed window size; `benchmark=1` turns dynamic resolution off and writes samples as JSON into `#fps[data-benchmark]`. Close other rendering pages first (an open preview pane skewed one run). Compare only like with like; when the machine throttles, compare A/B on the same page.

Call `vrlearn.benchmark.reset()` after changing the view or restarting playback to collect another sample on that page. It clears the previous report and repeats the two-second warmup and eight-second sampling window. `geometryBytes` deduplicates shared geometry buffers; `sceneBufferBytes` also includes instance storage. Compare these fields only with the same counting rules. For retained backing storage, use Chrome DevTools Protocol `HeapProfiler.collectGarbage` followed by `Runtime.getHeapUsage`, and disable back-forward caching when navigating between A/B pages so old documents cannot inflate memory. Keep loading outliers and separate cold startup from warm reloads.
