系统结构

系统结构

模拟器和编辑器由哪些模块组成，它们如何启动、每帧做什么、在哪些状态之间切换。

分层

React 负责低频的普通界面；TrafficEngine 持有唯一的渲染器和帧循环。每帧变化的数据（车辆位置、人物姿态、相机）留在引擎里，不进入 React state。

src/simulation/ 不引用 React、DOM 或 Three.js，所以检查脚本和测试可以在 Node.js 中直接运行同一套逻辑。

启动流程

  1. 挂载StrictMode 下创建 React 根src/app/main.tsx
  2. 创建引擎动态导入引擎，传入画布和界面容器createTrafficEngine()
  3. 并行加载场景、布局、路面、碰撞、事件索引、自由探索配置data/*.json · world/hikone.json
  4. 构建场景材质、街区模型（Worker）、信号灯、玩家buildEnvironment() · buildSignals()
  5. 标题菜单列出场景，等待开始screen = 'title'

加载失败时显示原因和重新加载按钮。引擎卸载时会取消未完成的请求和 Worker 任务，并按顺序释放资源。

每一帧

  1. 计时帧间隔上限 0.1 秒timer.getDelta()
  2. 分辨率需要时先调整画布AdaptiveResolution
  3. 逻辑玩家移动、交通、观察、遭遇；自由探索按 1/60 秒切片并逐片检查接触tick(dt)
  4. 环境水面、树叶、野生动物、太阳阴影定位light · wildlife
  5. 画面同步车辆与信号，选相机，更新 LODsyncCars() · LOD
  6. 绘制渲染并采样性能；界面只在文字变化时更新PaintRenderer

交通更新会把大于 1/30 秒的步长再细分。回放时用录制时间驱动车辆、人物、信号和相机，而不是重新模拟。

两种模式

场景练习自由探索
车辆来源场景文件中的车辆，按各自时钟出发持续车流 + 遭遇时在看不见的上游加入的车
何时结束到达终点或发生接触不结束；接触后回放，再从附近继续
反馈结果页：观察时长、事故车是否被看见每次遭遇后的简短提示 + 探索记录
入口start()startExplore()

车不会追着参与者跑，也不会为了撞人改时间。参与者的危险行为只会提高新司机成为危险司机的概率。闯红灯时，还会在横穿方向看不见的上游放出最多两辆反应慢的车。

交通与信号

  • 司机是持续的。每辆车出生时抽取反应时间、期望速度、制动力等参数；是否成为危险司机（闯红灯、超速、不让行）只决定一次，之后不变。
  • 信号用场景时间。SignalCycle.at(秒) 对同一时刻总是给出同一相位，所以暂停、回放时灯色和车辆一致。京桥路口是行人专用相位。
  • 司机看得见才会反应。司机按视线和预测判断冲突；步行红灯时，司机默认人行道上的人会在路缘停下，有人闯红灯进入时反应更慢。
  • 接触是物理结果。Traffic.hit() 用车身轮廓判断，场景标签不能绕过规则。

录制与回放

  1. 录制按固定间隔保存参与者与车辆快照Recorder.capture()
  2. 截取取接触前后的时间窗口Recorder.window()
  3. 规划相机回放开始前一次性规划镜头，避开遮挡ReplayCamera
  4. 播放在快照间插值，可切换俯瞰或驾驶席视角Replay · sample()

开启“减少动态效果”时，回放使用稳定的远景镜头。

编辑器

场景格式与模拟器共用 src/simulation/core/scenario.ts：导入时用 parseScenario() 检查，保存前用 validate() 给出错误和警告。用户保存不能覆盖 builtin-* 模板。

资源与生命周期

同一时间只有一个引擎。引擎通过 ResourceScope 登记自己创建的一切：网络请求、Worker、监听器、观察者、几何体和材质。卸载时按登记顺序取消和释放，React StrictMode 下反复挂载也不会泄漏。

编辑器同样用中止信号管理监听器、预览动画和计时器。
