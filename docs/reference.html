应用状态与帧循环

state更新与退出
title显示菜单。选择场景后，start() 进入 playing。
playing更新玩家、触发区、交通和录制。接触车辆后进入 impact，到达终点后进入 results。
impact播放倒地视点并保留事故后的录制片段，然后进入 replay。
replay使用录制时间更新车辆、人物、相机和信号。播放结束后停在最后一帧，激活 結果へ進む / Next 后进入 results。播放期间支持 スキップ / Skip。
results显示观察反馈。支持重新体验与回到 title。

renderer.setAnimationLoop() 每帧调用 tick(dt)。dt 最大为 0.1 秒。交通更新对大于 1 / 30 秒的步长细分。

帧内顺序为分辨率调整、逻辑更新、环境动画、阴影定位、相机选择、LOD 更新、绘制和性能采样。普通体验使用玩家相机，回放使用 replay.activeCamera，调试视角优先于两者。

run.recordingHead 复用逐帧头部快照。Recorder.capture() 只在采样到期时复制录制数据。

validateStructure() 要求终点宽度和深度至少为 0.5 米，起终点间距至少为 3 米。车辆路线至少包含两个点，速度范围为 5 至 80 km/h，启动延迟为 0 至 120 秒。

有效重复间隔满足 repeatMinSeconds ≤ repeatMaxSeconds。启用重复时，最短间隔至少为 1 秒。start 为 trigger 或 stopOnTrigger 为 true 时，场景必须包含宽度和深度都大于零的触发区。

validateOnMap() 检查起终点和路线是否位于道路上，同时检查墙体、模型名和触发区。validate() 返回 {level, message, target} 数组，level 为 error 或 warning。编辑器使用这些问题标记无效场景。

外部 JSON 的输入边界

parseScenario(text) 支持 UTF-8 BOM，先检查字段类型，再补默认值。失败抛出 ScenarioInputError，含 code: INVALID_SCENARIO、status: 400 和带 path 的 problems。编辑器允许保留语义无效的草稿供修改；模拟器的 createScenarioReader() 还会使用含 surfaces 的完整地图进行道路校验。地图只在导入或编辑器交接时请求，成功后复用，失败后可重试。导入失败保留当前选择，新选择不会被旧请求覆盖。

规范化与序列化

normalize() 补齐默认值。序列化时，除兼容的基础字段外，还会保留已支持的驾驶者（driver）、危险策略（hazardPolicy）和道路环境（environment）扩展；未知扩展字段不保证保留。

自由探索配置

world/hikone.json 由 resolveWorld() 解析；格式错误会列出全部问题后中止。

字段含义
starts步行与自行车的起点和朝向
recovery接触后可以继续的人行道地点
maxCars车流的车辆上限（24）
flows持续车流：路线引用、速度、首次出发与重复间隔（秒）
events遭遇绑定：所属组、方式、区域、进入方向、候选车辆
redEntryResponse闯红灯应答：参与的车流、速度、反应、制动、车辆数、冷却、持续时间
hiddenAdmission隐蔽放车：远距离、近距离、视野半角、停止线余量、搜索距离
noAdmission不允许放车的区域（路口内部）
props常驻停放的卡车，以及可被遭遇取出的停车位

同一冲突组（例如东侧人行横道的 01/02/05）一次只进行一个遭遇。每个遭遇的概率随参与者风险分数上升，但不会为零。

坐标与接触查询

场景文件、编辑器和交通逻辑使用地图坐标，单位为米。yaw 单位为度，从 +z 朝向开始顺时针增加。

位置转换toThree(x, y, z) = (-x, y, z)
朝向转换yawToThree(yaw) = -yaw × π / 180

src/three/scene/coords.ts 负责 Three.js 坐标转换。编辑器地图的 X 轴向右，Z 轴向上，屏幕像素 Y 轴与 Z 轴方向相反。

对象或查询实现
城镇路面与人行道高度为 0.01 米。独立路缘顶面为 0.16 米，地块为 0.15 米。城堡方向的坡路跟随地形。
Ground.heightAt()按空间格查询道路三角形，再求重心插值高度。
Obstacles使用 data/collision.json 的位网格、信号杆占地和停放车辆矩形。
Traffic.hit()使用交通车辆与参与者的平面接触范围。
CameraObstacles使用静态低精度模型的 CPU 三角形轮廓，查询相机遮挡。
GroundContact.minimumY()使用已摆出姿态的顶点求最低点，避免倒地人物和自行车穿过地面。

这些查询不依赖当前画面中哪些渲染网格被剔除。

车辆调度与信号

Traffic 将 route 转成 smoothRoute() 路径。pathAt() 按路径距离求位置，carPose() 计算车辆朝向和转向。junctionStops() 为路线生成停车线距离。

浏览器事件扩展

以下字段只在浏览器版中生效，Unity 版不保证兼容。

编辑器会保留 driver、environment、entrySpeedKmh 和 noStop。默认的自适应驾驶者可能违反部分规则；hazardPolicy 控制基准概率和危险行为时的概率。显式设置的 driver.behavior 会原样保留。旧版的 launch: "meet" 以及等待、超时字段已不再影响车辆出发。驾驶者与道路环境设置的完整说明见 RATIONALE.md（英文）。

SignalCycle.at(seconds) 返回复用的状态对象，字段为 id、eastWest、northSouth、walk、walkOn 和 remaining。负数和非有限时间按零处理。

SIGNAL_PERIOD 为 87 秒。区间中的 t 为场景时间对周期取余的结果。

signalRigs() 返回 5 组装置，共 6 个车行灯头和 8 个行人灯头。

所有行人灯共用 walk。flash 状态每秒前半秒点亮。上述秒数是模拟设置，不是现场控制器的实测配时。

src/three/scene/signal-layout.js 保存灯杆、灯头、牌面和朝向。src/three/scene/signals.js 创建实例，复用只读几何属性，保留各自的亮度数据。灯态仅在变化时更新。

录制与回放

Recorder.capture(time, head, cars) 保存参与者与车辆快照。采样到期前不写入数据，过期帧从缓冲区移除。

符号值单位
SAMPLE_INTERVAL0.05秒
BUFFER_SECONDS12秒
SECONDS_BEFORE_IMPACT8秒
SECONDS_AFTER_IMPACT1.6秒
GAZE_HALF_ANGLE35度
GAZE_MAX_DISTANCE60米
SIDE_CHECK_MIN35度
SIDE_CHECK_MAX150度

Recorder.window(from, to, cut) 返回时间窗口，并排除 cut 之前最后一次位置跳变以前的帧。sample() 对位置、朝向和转向作插值。

accidentAnalysis() 计算是否看见事故车、观察时长、最后一次观察时间和速度。crossingAnalysis() 计算左右观察时长与最近车距。

Replay 重建车辆、人物、自行车和驾驶席视角。ReplayCamera 在开始前规划轨迹，检查主体取景和遮挡，平滑后保存路径。播放阶段沿路径插值。减少动态效果偏好使用稳定的远景。

渲染资源与性能接口

buildEnvironment() 准备高低精度模型。environmentInstances() 按资产、LOD 和空间块组织实例。PigmentPalette 将材质颜色组织为共享数据，PaintRenderer 绘制场景，不运行后处理链。

LOD 和视锥剔除使用迟滞，视角未达到移动或转动阈值时复用选择结果。静态低精度物体进入太阳阴影缓存，移动车辆、人物和自行车使用 withBlobShadow()。阴影覆盖范围变化时才重绘静态阴影。

src/three/entities/vehicles.js 缓存车辆模型，只为可转向前轮准备独立部件。CameraObstacles 按几何体缓存 CPU 射线索引，每个实例保存自己的变换。临时回放遮挡物随回放释放。

编辑器与本地 API

src/editor/controller.ts 探测本地 API。API 不可用时，src/editor/store.ts 使用 localStorage，数据键为 vrlearn.editor.scenarios，回收区键为 vrlearn.editor.trash。

浏览器体验交接使用 vrlearn.editor.play 和 ?play=editor。两种存储方式都读取本仓库的模板。保存用户场景时，ID 不能以 builtin- 开头。

server/editor-api.mjs 在 VRLEARN_ROOT 指向的 Unity 项目包含 ProjectSettings 和 Scenarios 时启用。默认路径为兄弟目录 ../VRLearn。API 只回答回环地址请求，并拒绝跨站写入。

方法与路径请求或响应
GET /api/status响应 {server: true, root}。API 不可用时该路径返回 404。
GET /api/map浏览器地图 JSON 与路线提示。
GET /api/map/image地图 PNG。
GET /api/scenarios用户场景与本仓库模板列表，包含错误和警告数量。
GET /api/scenario?path=…指定相对路径的场景。模板位于 templates/。
PUT /api/scenarios/:id请求体为场景 JSON。规范化、序列化并保存，响应 {path, problems}。允许保存语义校验失败的草稿；JSON 语法或字段类型错误返回 HTTP 400 和 {error, code, problems}，不覆盖已保存文件。
DELETE /api/scenarios/:id将用户场景移到 Scenarios/.trash/。
POST /api/play请求 {path}，写入供 Unity 读取的 Scenarios/.play-request.json。
GET /api/play响应 {pending}。
GET /api/questadb 路径、应用包名与连接的头显。
POST /api/quest/sync请求可含 serial，将有效场景镜像同步到 Quest。

无效 ID、模板覆盖和请求 ID 不一致返回 400。跨站写入返回 403，未找到资源返回 404，大于 2,000,000 字节的请求体返回 413。浏览器存储容量不足返回 507。静态站点不提供 Unity 播放与 Quest 同步。
