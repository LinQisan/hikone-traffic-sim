# UX, DX and AX review — 2026-10-26

## Scope and dependency boundaries

Reviewed the simulator and editor entry points, their relative static imports, scenario input and storage boundaries, startup data use, reference generation and deployment checks. The browser module graph had no static import cycle. The boundaries below guided the changes; this review does not cover every generator or the optional Unity runtime.

| Boundary | Owner and contract |
| --- | --- |
| Participant flow | `src/app.js` connects title, practice, exploration, replay and results. Existing DOM ids and debug interfaces stay usable. |
| Scenario rules | `src/shared/scenario.js` owns defaults, serialization and validation for the simulator and both editor backends. `events/` remains the built-in source. |
| Rendering and startup | Native model workers and the runtime wall map prepare the scene. Full road-surface data belongs to optional geographic validation. |
| Editor storage | `editor/store.js` and `server/editor-api.mjs` retain their common request interface, protected template ids and editable invalid drafts. |
| Verification | `AGENTS.md` selects checks by impact; generated reference tables, Node tests and Vite build now have one local/CI entry point. |

## Confirmed problems and decisions

| Evidence before the change | Decision | UX / DX / AX result |
| --- | --- | --- |
| Importing a valid built-in through the custom-file path threw `map.surfaces is not iterable`: the simulator passed `walls.json` to road-surface validation. The same file validated against `map.json`. | Share a lazy `createScenarioReader()` between file import and editor handoff. Cache successful map loads and clear failed loads. | Custom practice and editor preview work; ordinary startup avoids the full-map request; one module explains and tests the resource contract. |
| Malformed vehicle/route types reached array operations, and malformed server writes produced generic failures. | Parse external text through shared `parseScenario()` before replacing state or saving. Return Japanese field paths and structured `INVALID_SCENARIO` errors with status 400. | Useful feedback, existing work retained, identical input rules at browser and server boundaries. |
| Simulator import used blocking alerts and had no pending-request ownership. Adding asynchronous map loading would let an old file replace a newer selection. | Put persistent status beside the file control, expose status/alert semantics, disable launch while validating, guard completion by request generation, and bring Start into view on success. | Retry and keyboard operation remain clear; choosing a built-in cancels the pending selection; state changes have an explicit owner. |
| Deployment ran tests and build independently of the source-derived reference check. | Use `npm run check` in both the project and Pages workflow; retain targeted commands for small changes. Document the decision and input contracts in `AGENTS.md`, the reference and rationale. | Faster discovery of stale docs and broken builds, fewer commands for developers and agents to reconstruct. |
| Editor API and Quest protocol tests silently skipped without a sibling Unity checkout, so CI did not exercise the same checks as this computer. | Always create a minimal temporary project per test process and fail if the fixture is unavailable. Keep the existing fake adb. | Storage and integration guards are checked before release, new developers need no Unity setup, and agents cannot mistake a skipped test for coverage. |

Compatibility decisions: keep defaults, centimetre-precision serialization, supported driver/environment/hazard extensions and optional `null` fallback values. Semantic errors remain editable in the editor; starting a practice still requires geographic validity. No new package dependency, scene/model/layout change or simulation-rule change was needed for this review.
