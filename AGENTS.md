# AGENTS.md

Independent browser traffic-safety practice tool, originally based on [VRLearn](https://github.com/LinQisan/VRLearn): the Hikone Kyobashi scene as an open exploration session where the 10 accident events occur as encounters (`world/hikone.json`), the same events and custom scenario JSON as standalone practice, plus a scenario editor (`editor/`). React UI, strict TypeScript simulation/control, native three.js geometry and Vite; run `npm ci` before development or checks. It does not collect experiment data; the exploration record stays in the tab unless the participant saves it.

Talk to the owner in Chinese. Code, comments, commits and these docs in English; README and UI in Japanese.

## Commands

```bash
node --test test/turning.test.mjs   # targeted example: choose the affected test file
npm test                          # full regression (includes the event checker); see Verification
npm run check                     # typecheck + generated docs + full regression + production build (also CI)
npm run typecheck                 # strict runtime/application types
npm run check:docs                # verify generated reference tables against source
npm run dev                       # http://127.0.0.1:8770/ ; add -- --host 0.0.0.0 for phones
npm run build                     # build dist/ for GitHub Pages; npm run preview to inspect
node tools/check_events.mjs [id]  # event purposes, with real sight lines
node tools/check_routes.mjs       # authored segments, editor cars and runtime bodies stay on roads
node tools/check_red_crossings.mjs [n] [walking|bicycle] [gaze°]  # open-world red crossings: contact rate by crossed road signal
node tools/sync.mjs --events-only # build simulator/editor built-ins from events/; no Unity needed
```

The runtime builds native geometry from construction programs in `models/` (`src/three/geometry/model-builder.js`, `src/three/geometry/model-vegetation.js`); Existing GLBs are offline fixtures; the optional export API creates separate GLB copies. Vite packages recipe transport automatically with `tools/pack_models.mjs`; `models/runtime.json` is generated metadata and `models/packed/` is disposable. After procedural author changes, compile recipes with `blender -b --factory-startup --python tools/build_native_models.py`, then rebuild collision. Native recipes are generated by that command; edit the procedural author or construct a new program with `ModelBuilder`.

Historical asset data comes from `../VRLearn` (`VRLEARN_ROOT`), in this order — Unity `Tools/VRLearn/Web/Export Scene For Web` → `blender -b --factory-startup --python tools/export_models.py` → `… tools/build_impressionist.py [-- --only NAME…]` → `node tools/sync.mjs` → `node tools/build_collision.mjs` → the applicable checks under Verification.

## Rules

Choose changes that improve participant UX, developer DX and agent AX together: reproduce the friction, trace its dependencies, preserve supported behavior, then verify the affected flow. Prefer one shared rule and one documented entry point over duplicated fixes or speculative restructuring. Input errors must identify the field, preserve the current work and allow retry. Keep startup-only resources separate from optional workflows.

1. **This project need not match VRLearn.** Its routes, timing and editor templates are owned here; `events/` is the built-in source for both the simulator and editor. Do not change the sibling Unity project unless asked. Existing geometry uses the imported map coordinates; only `src/three/scene/coords.ts` converts to three.js. Layout changes go in `src/world/generators/web-layout.js` or the relevant local generator.
2. **Keep heights consistent with the map** (carriageway and town footways 0.01, separate 15 cm kerb caps 0.16, town plots 0.15; castle approach follows terrain). Avoid ad hoc renderer offsets; update the authoritative geometry when changing heights. Ground models are pressed just under the roads in `world.js`.
3. **Never hand-edit generated files in `data/`.** Rebuild built-ins with `node tools/sync.mjs --events-only`, which does not import Unity assets or templates. A full sync imports upstream geometry and the currently compatible scenario model; review those changes. Browser format changes may be made locally in `src/simulation/core/scenario.ts`; Unity compatibility is optional, and a later full sync must not erase local extensions.
4. **Events:** edit `events/`, never `data/scenarios/`. Each must pass the checker: cautious traversal reaches the goal in the ordinary-driver reference, and cars appear hidden or far away. Departures use independent clocks. Actual participant behavior changes the probability of a persistent rule-breaking driver, with a nonzero baseline for compliant play. Contact is a physical outcome, never a requirement; accident labels alone cannot bypass rules or chase the player. Open-world encounters reference event routes from `world/hikone.json` and admit cars only at hidden, clear upstream points.
5. **Relative URLs only** — the site is served from a sub-path on GitHub Pages. **A push to `main` deploys the Vite build through GitHub Actions.**
6. **Even frames:** about 120 draw calls; nothing moving casts into the sun's shadow map (use `withBlobShadow`); no per-frame allocation in hot paths; no post-processing. Measure rendering changes with `?benchmark=1`, A/B on the same page — absolute fps on this laptop is not evidence.
7. **After model recipe or layout changes** rebuild `data/collision.json`; every spawn and way to the goal must stay free (`test/obstacles.test.mjs`).
8. **Keep accessibility working:** announcements, focus moves, keyboard play (Q/E look), 44 px touch targets, reduced motion, forced colours.
9. **Every state can be left** to the menu, and the replay always reaches the results.
10. **The editor server answers this computer only** and refuses cross-site writes; user saves cannot overwrite templates (`builtin-*`). Both backends open this project's templates. `src/components/editor/EditorApp.tsx` ids are used by `src/editor/controller.ts` — restyle freely, keep the ids.

## Architecture

- React owns ordinary UI and mount lifetimes (`src/app/App.tsx`, `src/components/editor/EditorApp.tsx`). Native Three.js owns one renderer and loop (`src/three/engine/TrafficEngine.ts`). Keep frame-rate objects out of React state; publish changed UI slices only.
- `src/simulation/` and data types must remain React/DOM/Three.js independent. Keep saved version-one scenarios and session logs compatible. Do not change clocks or driver parameters during a type migration.
- New runtime logic uses strict, erasable TypeScript; unchanged procedural visuals remain JavaScript with typed boundaries. Do not use `any`, blanket suppressions or relaxed checks to make a migration pass.
- A mounted engine owns cancellation, workers, input and resource disposal. Release shared prototypes only at whole-engine teardown; React StrictMode stays enabled. Editor SVG drawing remains native; ordinary forms are React components.
- `src/export/` defines versioned GLB/JSON exchange, independent of React. GLB does not export simulation behavior or custom brush shaders. See [migration and verification](docs/react-typescript-migration.md).

## Verification

Choose the smallest checks that cover the affected behavior, not a fixed suite for every change. Existing tests remain available; do not add tests for prose, pure formatting or cosmetic constants, or tests that only repeat the implementation. Add a focused regression test for an uncovered behavior fix.

| Change | Required checks |
| --- | --- |
| Docs/comments/pure formatting | Review content/paths and `git diff --check`; no browser or test suite. |
| CSS, copy or cosmetic values | Inspect the affected page/view, keyboard/touch reachability and console; no unrelated simulation tests. |
| Isolated logic fix | `node --test test/<affected>.test.mjs`; use `--test-name-pattern` before the file path for one regression case. |
| Vehicles/steering | `test/turning.test.mjs`; add `test/logic.test.mjs`, `test/crash.test.mjs` or `test/bicycle.test.mjs` only for the behaviors affected. |
| Art/models/layout/collision | Regenerate the affected outputs and collision grid; run `test/art.test.mjs` and `test/obstacles.test.mjs`. Check the affected view. Run `test/performance.test.mjs` and benchmark only when rendering workload/LOD/shadows change. |
| Editor storage/server/Quest bridge | Corresponding `test/editor-store.test.mjs`, `test/editor-server.test.mjs` and/or `test/editor-quest.test.mjs`. |
| Open world (`world/`, `src/world/scenes/world.ts`, `src/simulation/events/ScenarioManager.ts`) | `test/world.test.mjs` and `test/scenario-manager.test.mjs`; explore the affected area in its mode. Flow or truck changes also need `test/routes.test.mjs`. |
| One event | `node tools/check_events.mjs <id>` and play that event; route changes also need `node tools/check_routes.mjs` and `test/routes.test.mjs`. Shared timing/contact changes require full regression. |
| Scenario format/sync | Affected editor/logic tests and `test/scenario-import.test.mjs`; check both editor backends against the browser events. File import and editor handoff must use `parseScenario()`; runtime geographic validation needs the full map with `surfaces`. Run Unity's `ScenarioModel` tests only when changing the optional Unity integration. |
| Cross-cutting flow, replay, coordinate/height conventions, shared timing/contact, dependency changes or uncertain impact | `npm run check`; check a walking and a cycling event for affected experience changes. |

Read the selected test counts; zero tests or a skipped required integration test do not prove the change. Expand checks after failures/new dependencies. Reuse passing results while tested inputs remain unchanged; hand-off, commit or push alone does not require repeating them. A push to `main` is still a deployment, so complete the applicable checks before pushing.

Editor API and Quest protocol tests create isolated project fixtures and use a fake adb; they must run in a standalone checkout without a sibling Unity project. They do not prove a real Unity/Quest session.

## Before handing off

- Complete the applicable checks above and run `git diff --check`. For visible changes, load the affected page without console errors (headless Chrome screenshots are fine for looks); local cosmetic changes need no unrelated event playthrough.
- Commit or push only when asked; never force-push.
- Say what changed, what was verified, and what was not (e.g. no real phone).
